# 风格条目统一 schema

每个 `styles/<id>.md` 由 frontmatter 加 8 节组成，缺任何一节即不合格。

## Frontmatter

```markdown
---
id: acid                     # 与文件名一致，即 style: 的取值
name_zh: 酸性设计
name_en: Acid Graphics
lineage: ""                  # 流派/年代/代表人物，写事实，来源写进 §7
status: draft | ready | placeholder
nearest: [cyber-neon]        # 最容易混淆的风格 id，用于 §8 区分句
overlays: []                 # 引用的第三方 overlay 文件名
exception: false             # 是否与默认纪律冲突、需走例外通道（酸性为 true）
---
```

## 8 节与合格下限

| 节 | 内容要求 | 合格下限 |
|---|---|---|
| §1 判据 | 看图可判「是 / 否」的特有特征 | ≥3 条，且不得与任何其他条目的判据句相同 |
| §2 反模式 | 这套风格特有的失败方式（不是通用的「对比不足」） | ≥3 条，同上不得复用 |
| §3 排版机制 | 网格或反网格规则、层级做法、对齐轴、破格的条件 | 至少说明「结构从哪来」和「在哪里允许打破」 |
| §4 色彩 | 色彩关系（互补/邻近/三角/分裂互补等）、明度结构、屏幕与印刷各自怎么处理；可给示例色但须标注「示例」 | 关系描述必填，hex 可选 |
| §5 字体 | 中文按 `typography/cn-type-classes.md` 的三型归类，英文写分类；标注授权状态 | 中英各至少一个方向 |
| §6 提示词出口 | 按 `prompt-export/interface.md` 契约给正向片段、反向片段、分工具写法 | 5 个工具字段齐全（Flux 可写「转正向约束」） |
| §7 来源与既有实现 | 事实来源、本机已有实现的 overlay 引用 | 至少 1 条可追溯来源 |
| §8 区分度自检 | 一句话写清与 `nearest` 的差别 | 必填 |

## §9 例外通道（仅限 `exception: true`）

- `exception: true` 的条目可以、也应当加第 9 节「§9 例外通道」，写明本条目覆盖哪些默认纪律、覆盖范围到哪里为止。
- lint：只有 `exception: true` 时才允许出现 §9；`exception: false` 的条目出现 §9 即不合格。无论是否为例外条目，§1–§8 仍全部必填。
